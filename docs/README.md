# DCN Proxy Server Documentation

## โครงสร้างและการทำงานของระบบ

### ภาพรวมของระบบ
DCN Proxy Server เป็นแอปพลิเคชันตัวกลางที่เชื่อมต่อระหว่าง API ของระบบประชุม Bosch DCN กับไคลเอนต์ที่ต้องการรับข้อมูลสถานะการประชุม โดยระบบจะทำหน้าที่ดังนี้:

1. ดึงข้อมูลสถานะไมค์จาก API ของระบบ Bosch DCN
2. แปลงข้อมูลให้อยู่ในรูปแบบ XML ที่เหมาะสมสำหรับไคลเอนต์
3. ส่งข้อมูลไปยังไคลเอนต์ทั้งหมดที่เชื่อมต่ออยู่ผ่าน TCP
4. ให้บริการ REST API สำหรับการตั้งค่าและตรวจสอบสถานะของระบบ

### โครงสร้างของโปรเจกต์
โครงสร้างไฟล์ของโปรเจกต์ แบ่งเป็นส่วนต่างๆ ดังนี้:

```
phi-DCN/
├── client/
│   ├── api/          - จัดการการเชื่อมต่อกับ API ของ Bosch DCN
│   ├── config/       - จัดการการตั้งค่าของระบบ
│   ├── proxy/        - จัดการการเชื่อมต่อกับไคลเอนต์และส่งข้อมูล
│   ├── server/       - จัดการ REST API สำหรับการตั้งค่า
│   ├── xml/          - จัดการการแปลงข้อมูลเป็น XML
│   └── main.go       - จุดเริ่มต้นของแอปพลิเคชัน
├── config/           - ไดเรกทอรีเก็บไฟล์การตั้งค่า
│   └── config.ini    - ไฟล์การตั้งค่า
├── logs/             - ไดเรกทอรีเก็บไฟล์บันทึกข้อมูล
└── docs/             - เอกสารประกอบ
```

### การทำงานของแต่ละส่วน

#### 1. ส่วนการตั้งค่า (config)
- `config.go` - จัดการการอ่านและบันทึกการตั้งค่าลงไฟล์ `config.ini`
- การจัดการการตั้งค่าสามารถทำได้ผ่าน REST API หรือแก้ไขไฟล์ `config.ini` โดยตรง
- มีระบบสำรองการตั้งค่าก่อนการเปลี่ยนแปลงและการคืนค่าการตั้งค่าเมื่อเกิดข้อผิดพลาด

#### 2. ส่วนการเชื่อมต่อกับ API (api)
- `speakers.go` - จัดการการเชื่อมต่อกับ API ของ Bosch DCN เพื่อดึงข้อมูลสถานะไมค์
- `rest.go` - จัดการ REST API สำหรับการตั้งค่าและตรวจสอบสถานะของระบบ

#### 3. ส่วนการจัดการไคลเอนต์ (proxy)
- `proxy.go` - จัดการการเชื่อมต่อกับไคลเอนต์และส่งข้อมูล XML ไปยังไคลเอนต์
- รองรับการเชื่อมต่อจากหลายไคลเอนต์พร้อมกัน
- มีระบบจัดการการเชื่อมต่อที่ไม่ได้ใช้งาน

#### 4. ส่วนการแปลงข้อมูล (xml)
- แปลงข้อมูลสถานะไมค์จาก API ให้อยู่ในรูปแบบ XML ที่เหมาะสมสำหรับไคลเอนต์
- สนับสนุนการเข้ารหัส UTF-16LE สำหรับ XML

## การติดตั้งและการใช้งาน

### ความต้องการของระบบ
- Go 1.22 หรือสูงกว่า
- ระบบปฏิบัติการ Windows, macOS, หรือ Linux

### วิธีการติดตั้ง
1. Clone โปรเจกต์จาก GitHub:
```
git clone https://github.com/username/phi-DCN.git
```

2. เข้าไปยังไดเรกทอรีของโปรเจกต์:
```
cd phi-DCN
```

3. สร้างไฟล์ binary:
```
go build -o dcn-proxy
```

### วิธีการใช้งาน
1. เริ่มต้นใช้งานแอปพลิเคชัน:
```
./dcn-proxy [REST_API_PORT]
```
โดย `REST_API_PORT` คือพอร์ตสำหรับ REST API (ค่าเริ่มต้นคือ 3002)

2. ตั้งค่าการเชื่อมต่อกับ API ของ Bosch DCN ผ่าน REST API:
```
curl -X POST http://localhost:3002/api/config -H "Content-Type: application/json" -d '{"APIHost":"192.168.1.100","APIPort":"80","APIPath":"/api/speakers"}'
```

3. ตรวจสอบสถานะของระบบผ่าน REST API:
```
curl http://localhost:3002/api/status
```

## คุณสมบัติด้านความปลอดภัยและประสิทธิภาพ

### ความปลอดภัย
- จำกัดจำนวนการเชื่อมต่อสูงสุด (5 การเชื่อมต่อ)
- มีการตรวจสอบความถูกต้องของข้อมูลที่รับเข้ามาและส่งออกไป
- ใช้งานในเครือข่ายภายในเท่านั้น (local network)

### ประสิทธิภาพ
- ใช้ connection pooling และ buffer pool เพื่อลดการใช้หน่วยความจำ
- ใช้ goroutine ในการจัดการการเชื่อมต่อเพื่อเพิ่มประสิทธิภาพ
- มีการใช้ timeout และ retry mechanism เพื่อเพิ่มความเสถียร

### การจัดการข้อผิดพลาด
- บันทึกข้อผิดพลาดลงในไฟล์ log
- มีระบบ rollback เมื่อเกิดข้อผิดพลาดในการตั้งค่า
- มีการแจ้งเตือนเมื่อเกิดข้อผิดพลาดผ่านทางคอนโซล

## การเพิ่มเติมและการปรับแต่ง

### การเพิ่มฟังก์ชันใหม่
1. เพิ่มการรองรับ API ใหม่:
   - เพิ่มฟังก์ชันใหม่ในไฟล์ `api/speakers.go`
   - เพิ่มการแปลงข้อมูลในไฟล์ `xml/xml.go`

2. เพิ่มการรองรับโปรโตคอลใหม่:
   - สร้างไฟล์ใหม่ในไดเรกทอรี `proxy/` สำหรับการจัดการโปรโตคอลใหม่

### การปรับแต่งการตั้งค่า
1. เพิ่มการตั้งค่าใหม่:
   - เพิ่มฟิลด์ใหม่ในโครงสร้าง `AppConfig` ในไฟล์ `config/config.go`
   - เพิ่มการอ่านและบันทึกการตั้งค่าใหม่ในฟังก์ชัน `LoadConfig` และ `SaveConfig`

## การแก้ไขปัญหา

### ปัญหาการเชื่อมต่อกับ API
1. ตรวจสอบการตั้งค่าการเชื่อมต่อ API:
```
curl http://localhost:3002/api/config
```

2. ตรวจสอบสถานะการเชื่อมต่อ API:
```
curl http://localhost:3002/api/status
```

3. ตรวจสอบไฟล์ log เพื่อดูข้อผิดพลาด:
```
cat logs/error_YYYY-MM-DD.log
```

### ปัญหาการเชื่อมต่อกับไคลเอนต์
1. ตรวจสอบสถานะของ TCP Server:
```
curl http://localhost:3002/api/server
```

2. ตรวจสอบรายการไคลเอนต์ที่เชื่อมต่ออยู่:
```
curl http://localhost:3002/api/clients
```

3. ตรวจสอบไฟล์ log เพื่อดูข้อผิดพลาด:
```
cat logs/error_YYYY-MM-DD.log
```

## การพัฒนาในอนาคต

- เพิ่มการรองรับการเชื่อมต่อแบบ WebSocket
- เพิ่มการรองรับการเข้ารหัสข้อมูล
- เพิ่มหน้าเว็บสำหรับการตั้งค่าและตรวจสอบสถานะ
- เพิ่มการรองรับการแจ้งเตือนผ่านทางอีเมลหรือ webhook
